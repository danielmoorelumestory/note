## Context

四年高低由 `getFourYearExtremes(code)` 获取：直连腾讯月K（前复权），取各月最高价的最大值和最低价的最小值，窗口为“今年及前四个自然年”（今年是 2026 年则从 2022-01-01 起），结果按代码按天缓存在 localStorage。“已保存标的”页的 `loadExtremes` 对每个标的串行调用它。

云端已有：`daily_bars`（未复权日K，含最高/最低价）、`daily_offsets`（前复权偏移）、`daily_meta`（每个标的日K 已回填到的起点）。回填起点取“最早建仓日”与“四年前 1 月 1 日”中较早者，所以只要某标的回填过，它的 `backfilled_from` 一定不晚于四年窗口的起点，云端日K 足以覆盖这个窗口。月K 的最高/最低价本来就等于其所含日K 的最高/最低价，因此由日K 聚合得到的结果与现在口径一致。

## Goals / Non-Goals

**Goals:**
- 一次请求取回多个标的的四年前复权最高/最低价，替代逐个标的直连。
- 口径与现有一致（窗口、前复权、最低价排除 0）。
- 云端数据缺失或不可用时，行为与现在完全一致。

**Non-Goals:**
- 不存月K/年K，不新增表。
- 不改四年窗口的定义。
- 不改页面上高低步数的计算和展示。

## Decisions

**1. 接口：`GET /daily/extremes?codes=a,b,c`，一次最多 50 个代码。**
返回 `{ window: { from: "2022-01-01" }, extremes: { "601318": { high, low, to } } }`，`to` 为参与计算的最后一个交易日（便于判断数据新旧）。只返回有数据的标的，缺失的直接不出现在结果里。
备选：每个标的单独一个接口。放弃原因：页面打开时 12 个标的就是 12 次请求，违背“减少请求”的目标。

**2. 聚合在 SQL 里完成，前复权价 = 价格 − 当日偏移。**
`MAX(high − COALESCE(offset, 0))` 与 `MIN(low − COALESCE(offset, 0))`（`low > 0` 的行），按代码分组，窗口条件为 `date >= 窗口起点`。沿用现有 `/daily` 对缺偏移日期按未复权处理的约定。
备选：先取回全部日K 在 Worker 里算。放弃原因：数据量大且没必要，SQL 聚合一次完成。

**3. 只返回该密钥名下已保存标的的结果，且必须已回填。**
与 `/daily` 的规则一致：代码不属于该密钥的已保存记录则忽略；没有 `daily_meta` 记录（没回填过）的标的不返回，由前端回退。本接口只读，不触发任何抓取或写入，所以不会被滥用成腾讯代理。
备选：没回填时按需回填。放弃原因：聚合接口一次涉及多个标的，按需回填会让一次请求变得很慢且容易超出请求预算；缺失的标的由前端回退，下次定时抓取或 `/daily` 读取时就会回填。

**4. 前端：先批量读云端，缺失的标的再逐个回退。**
`loadExtremes` 先对所有待加载的标的发一次 `/daily/extremes`，立即把拿到的结果渲染出来；没有拿到的（无密钥、请求失败、云端没有该标的）再按现有方式逐个调用直连月K 的 `getFourYearExtremes`。回退路径与现有的按天缓存保持原样。

**5. 当天数据的时效。**
云端日K 在收盘后（15:10 起）才包含当天；盘中或收盘前，云端结果不含当天，而直连月K 含当天的部分数据。页面算“距高低点多少步”时使用现价，且步数下限为 0，所以当天创出新高/新低时只会短暂显示 0 步，不会出错，下一次抓取后自然修正，不做额外处理。

## Risks / Trade-offs

- [云端结果比直连少当天数据] → 影响仅在当天创新高/新低时的数值，且步数有下限保护，可接受。
- [某标的上市不足四年] → 窗口内只有上市以来的数据，与现有行为一致（月K 同样只有上市以来）。
- [`daily_offsets` 偏移比日K 滞后（除权日当天）] → 与 `/daily` 一致，由定时抓取的偏移重算机制修正，不在本变更处理。
- [一次查询涉及多个标的、数据行数较多] → 12 个标的四年约 1.2 万行，SQL 聚合轻量；代码数量上限 50 防止滥用。

## Migration Plan

1. 部署 Worker（无新表，无需建表）。
2. 部署前端。云端接口不可用或旧版 Worker 返回 404 时，前端回退为现有的直连方式，不会出错。
3. 回滚：重新部署上一版 Worker 与前端即可。
