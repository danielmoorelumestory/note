## Context

`simulateGrid` 对每个交易日（建仓日除外）计算 `buyPrice = lastTrade − step + rebound`、`sellPrice = lastTrade + step − pullback`，当日 `low ≤ buyPrice` 就按 `buyPrice` 买入，否则 `high ≥ sellPrice` 就按 `sellPrice` 卖出（每日最多一笔，买入优先）。步长、反弹、回落可按日期分段（`paramHistory`）。结果类型里早已有未使用的 `lowSince`、`highSince` 字段。手动增删叠加在模拟结果上（`applyLedger`），最新一行变化时以它为锚点重新模拟（`anchor`）；备份用同一套模拟，并带“重新模拟”开关关闭。

日线数据只有开高低收，看不出当天先低后高还是先高后低；云端已有最近几个交易日的 1 分钟线，但回测历史多数更早，无法普遍使用。

## Goals / Non-Goals

**Goals:**
- 实现真实的反弹买入 / 回落卖出，成交价取极值 ± 反弹/回落。
- 跨日跟踪极值，处理“第一天跌破没反弹、第二天才反弹”。
- 与手动增删、锚点续跑、备份对比、参数分段兼容。

**Non-Goals:**
- 不做倍投、同日多笔成交。
- 不用分钟线精确判断先后顺序（日线宽松口径）。
- 不改手续费、份额取整等其他规则。

## Decisions

**1. 状态：自上次成交起的 `runLow` / `runHigh`。**
每个交易日先把当日 `low`/`high` 并入 `runLow`/`runHigh`，再判断。成交（实际入账）后清空；锚点生效时也清空，之后重新累计。
备选：每天只看当天极值。放弃原因：无法表达“前一天跌破、后一天反弹”，也与用户描述的跨日场景不符。

**2. 买入判定与成交价。**
`armed = runLow ≤ tick(lastTrade − step)`（等于也算，用户例子里最低价恰好等于步长线）；`trigger = tick(runLow + rebound)`；`armed 且 当日 high ≥ trigger` 时买入，成交价 = `clamp(trigger, 当日 low, 当日 high)`。当日开盘跳空高于触发价时，价格被限制在当日最低价，避免出现当天根本没出现过的价格。卖出完全对称（`runHigh ≥ lastTrade + step`，`trigger = runHigh − pullback`，当日 `low ≤ trigger`）。
反弹确认用“当日最高价 ≥ 最低点 + 反弹”的宽松口径（已与用户确认）：先高后低的日子也可能被算作反弹，是日线数据的固有局限。

**3. 成交未入账时不清空跟踪。**
买入份额不足一手、卖出无持仓时不成交，此时保持原有的 `lastTrade` 和极值，等下一天重新判断（与现有“不成交就什么都不变”一致）。

**4. “预计下次买卖价”。**
结果里的 `nextBuy`：`armed` 时取 `tick(runLow + rebound)`，否则取 `tick(lastTrade − step + rebound)`；`nextSell` 同理。同时填充已有的 `lowSince` / `highSince`（尚未跌破/突破时为 `undefined`）。`applyLedger` 在“最新一行就是模拟最后一笔”或“以最新一行为锚点重新模拟”时直接使用模拟结果里的这些值；只有手动成交在最上面且没有重新模拟时（备份口径）才退回公式。

**5. 与锚点、跳过日期、备份的关系保持不变。**
锚点生效日重置 `lastTrade` 与两个极值；“被删除成交日”的跳过逻辑照旧，跳过的日子不成交但极值照常累计。备份快照与续跑沿用同一套模拟；规则版本从 4 升到 5，`upgradeBackup` 会按新规则重算旧备份的快照，保证“备份时”与“纯网格续跑”口径一致。

**6. 规则版本与迁移。**
`RULES_VERSION` 4 → 5。已保存记录在页面打开时本来就会按最新行情重算，所以无需迁移脚本；云端存的旧 `result` 在下次保存或同步时覆盖。

## Risks / Trade-offs

- [日线先后顺序不可知，宽松口径会高估反弹] → 已与用户确认采用；说明文字里注明口径。
- [所有历史回测结果变化，旧备份的“备份时”数字被重算] → 规则版本升级的既有机制；上线前用全部真实记录做新旧对比，逐条核对变化。
- [成交价限制在当日区间可能与“触发价”不同] → 仅在跳空时发生，结果更贴近真实可成交价格。
- [跨日跟踪使“预计下次买入价”随最低点下移而变动] → 页面提示同步说明“已跌破步长线，反弹到 X 即买入”。

## Migration Plan

1. 实现并通过单元式测试（构造行情）与真实记录对比。
2. 推送前端；打开页面即按新规则重算。
3. 回滚：恢复 `RULES_VERSION=4` 与旧触发逻辑即可，数据结构未变。
